Findings (19)
----------------------------------------------------------
  [CRITICAL] [GQ-001] Introspection exposed
      Evidence: Introspection returned the full schema (12 types) with NO token — anyone on the internet can read it.
      Fix: Disable introspection in production (and block __schema and __type for anonymous users).
  [HIGH] [GQ-003] No depth limit
      Evidence: The API answered a depth-50 query (cost ~2601) and never refused — no depth limit was found up to depth 50.
      Fix: Enforce a query-depth limit (5–10 is typical) before the query reaches the engine.
  [HIGH] [GQ-004] Batching enabled
      Evidence: Array batching works: one request with 100 queries returned 100 responses — a rate-limit bypass and a DoS amplifier.
      Fix: Disable array batching, or cap the batch size (10 is a common limit) and count batched operations against the rate limit.
  [HIGH] [GQ-005] Alias overloading
      Evidence: Alias overloading works: one query with 101 aliases returned data for the last alias (a100) — the engine resolved 101 copies of the same field.
      Fix: Limit the number of aliases per query (and dedupe identical fields before execution).
  [MEDIUM] [GQ-006] Field duplication
      Evidence: Field duplication accepted: the same field 50 times in one selection set was executed without complaint.
      Fix: Deduplicate identical fields before execution, and count duplicates towards the complexity limit.
  [MEDIUM] [GQ-007] Directive overloading
      Evidence: Directive overloading accepted: one field with 10 unknown directives executed without complaint.
      Fix: Limit the number of directives per query, and reject unknown directives instead of ignoring them.
  [HIGH] [GQ-008] Field returns data without auth
      Evidence: Field 'me' returns data with NO token: object[3 keys]
      Fix: Enforce authorization on 'me' — check the token before the resolver runs, not after.

  [CRITICAL] [GQ-009] IDOR — another user's object
      Evidence: IDOR: the scan token (user 1) fetched ANOTHER user's object: user 2; user 3
      Fix: Scope object access to the owner (or an admin) — check the token's user id against the requested id in the resolver.
  [CRITICAL] [GQ-011] Mutation without auth
      Evidence: Mutation 'ping' executes with NO token.
      Fix: Require authentication for every mutation — mutations change state, queries only read it.
  [CRITICAL] [GQ-011] Mutation without auth
      Evidence: Mutation 'updateProfile' executes with NO token.
      Fix: Require authentication for every mutation — mutations change state, queries only read it.
  [MEDIUM] [GQ-014] GET-based queries (CSRF angle)
      Evidence: GET-based queries work: the same query runs over GET (curl 'http://127.0.0.1:33641/graphql?query={%20__typename%20}'). If this API ever uses cookie auth, that is a CSRF vector.
      Fix: Accept GraphQL only over POST with a JSON body, or require a CSRF token / custom header on GET.
  [HIGH] [GQ-013] Sensitive field exposed
      Evidence: Sensitive field exposed: passwordHash returned without a token: string[38 chars]
      Fix: Never expose password hashes (or secrets/tokens) through the API — remove the field from the schema, or gate it behind an admin-only resolver.
  [HIGH] [GQ-017] Subscriptions supported
      Evidence: Subscriptions supported: HTTP subscription returns event data — a live event stream is an unauthenticated push channel and a denial-of-service shape (one client, many open streams).
      Fix: Disable subscriptions unless the API needs them; require authentication before the subscription is accepted, and cap concurrent subscriptions per client.
  [MEDIUM] [GQ-018] Persisted queries accepted (APQ)
      Evidence: Persisted queries accepted (APQ): the hash-only request was answered PersistedQueryNotFound (the server looked the hash up) and the hash+query request registered and executed — clients can run queries by hash alone, which bypasses any inspection that reads the query text.
      Fix: Disable APQ unless clients need it; if it is needed, allow only hashes registered at deploy time, and apply the same depth / complexity / auth checks to persisted queries as to plain ones.
  [HIGH] [GQ-019] File upload accepted
      Evidence: File upload accepted: the multipart upload executed and returned object[2 keys] — an upload endpoint is a classic attack surface (stored content, parsing, size).
      Fix: Disable file uploads unless the API needs them; validate the file type and size server-side, store uploads outside the web root, and require authentication for the upload mutation.
  [LOW] [GQ-016] No rate limiting observed
      Evidence: No rate limiting observed: 20 identical queries in a row all answered (no 429, no slowdown). Absence of evidence is not proof — but nothing throttled the flood.
      Fix: Add per-client rate limiting (and count batched operations against it).
